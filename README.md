# localai

Monorepo of web apps generated by a **local AI agent** (Hermes + Qwen running on a local LLM server).
Every app is showcased at **[localai.ponkcoding.com](https://localai.ponkcoding.com)** — hosted on GitHub Pages, deployed automatically by GitHub Actions.

No cloud AI APIs were involved. Everything here was written by a local model.

## Live

| URL | What |
|---|---|
| `https://localai.ponkcoding.com/` | Landing page / app showcase |
| `https://localai.ponkcoding.com/<slug>/` | Each individual app |

## Repository layout

```
localai/
├── apps/<slug>/            # one folder per app, fully self-contained
│   ├── app.json            # required manifest metadata
│   └── ...                 # any stack: vanilla JS, React/Vite, Angular, ...
├── landing/                # showcase page served at the root domain
├── scripts/
│   ├── new-app.sh          # scaffold a new app (vanilla | vite)
│   ├── build-manifest.mjs  # scan apps/*/app.json -> manifest.json
│   └── ci-detect.mjs       # list app slugs changed in a push
├── .github/workflows/
│   └── ci-cd.yml           # path-filtered CI/CD -> GitHub Pages
└── PLAN.md                 # project conventions & progress log (source of truth)
```

## How CI/CD works

One workflow (`.github/workflows/ci-cd.yml`), three jobs:

1. **detect** — `git diff` against the previous commit to find which `apps/<slug>/` folders changed.
2. **build** — a matrix builds **only the changed apps**. Each app declares its own build command and output folder in `app.json`, so any stack works.
3. **deploy** — merges the freshly built apps into the existing site (unchanged apps are kept from the previous deploy), regenerates `manifest.json`, and publishes via `actions/deploy-pages`.

So a change in `apps/app-1/` rebuilds and redeploys **only app-1**. A push that touches only `landing/` or an `app.json` just refreshes the showcase.

## Adding a new app

```bash
scripts/new-app.sh my-app vanilla   # static HTML/CSS/JS
scripts/new-app.sh my-app vite      # Vite (React/Svelte/vanilla-bundled)
```

Then edit the code, set `"status": "live"` in `apps/my-app/app.json`, commit and push.
The app goes live at `localai.ponkcoding.com/my-app/`.

For other stacks (e.g. Angular): scaffold manually, then create `app.json` with the right
`build` command and `dist` folder. Remember the base path rule below.

### The golden rules

1. **slug = folder name = URL route.** `apps/ayam-run/` → `/ayam-run/`.
2. **Every app is self-contained** — its own `package.json` and lockfile. No shared workspaces.
3. **Base path**: bundlers must build with base `/<slug>/`
   (Vite: `base: '/<slug>/'`, Angular: `--base-href /<slug>/`).
   Vanilla JS: use relative asset paths (`./style.css`).
4. **`app.json` is required** in every app folder:

   ```json
   {
     "name": "Display Name",
     "slug": "my-app",
     "description": "one line",
     "stack": "vanilla-js | vite | angular | ...",
     "status": "live | draft",
     "created": "YYYY-MM-DD",
     "build": "npm ci && npm run build",
     "dist": "dist"
   }
   ```

   `"build": ""` means static — files are copied as-is (`"dist": "."`).
